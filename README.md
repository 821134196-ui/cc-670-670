# 工厂危险作业监护人替换与现场复核系统

危险作业进行中更换监护人时，班组必须**先停工**，把风险与隔离措施交接清楚、双方签认后，
再由接班人**申请复工**、班组长复核批准。系统对「接班人资质、许可有效期、现场是否有人监护」
做硬性卡控，并完整留痕换班空档与交接时间线。

- **后端**：Python · FastAPI · SQLAlchemy · SQLite
- **前端**：Vue 3 · Vite（原生 SPA，无 UI 框架依赖）
- **门禁 / 通知**：本地接口模拟（可模拟延迟到达的门禁回执）
- **一条命令启动**：`./run.sh`

## 业务流程

```
作业进行中
   │  原监护人发起「停工交接」（作业立即 paused）
   ▼
交接页带出：作业许可 + 风险 + 隔离措施 + 未完成事项
   │
   ├─ 原监护人到现场核对 → 本人账号签认（outgoing）
   ├─ 接班人  到现场核对 → 本人账号签认（incoming）
   │      （门禁记录双方在场；离场/到场时间形成无人监护空档）
   ▼
双方签认完成 → 接班人申请复工
   ▼
班组长复核：查看无人监护时间段 + 复工条件
   ▼
系统硬校验通过 → 批准复工（监护人变更、作业 running）
```

### 复工三不原则（系统强制，班组长也无法放行）

1. **接班人资质不符**（证书类型不匹配，或证书已过期）→ 拒绝；
2. **作业许可无效**（超过有效期或已撤销）→ 拒绝；
3. **现场无人监护**（接班人无有效在场刷卡记录）→ 拒绝。

此外：双方未完成签认也不能复工。

### 关键合规规则与实现

- **一人一账号、禁止代签**：所有写操作携带本人 `X-User-Login`；
  签认人必须与交接中该角色绑定的人员一致，同一账号不能签两个角色，替他人签直接 403。
- **重复提交幂等**：同一作业同时只允许一条生效交接（部分唯一索引 `active=1`），
  重复发起返回冲突；同一角色重复签认返回首条记录，**不产生第二次交接/第二条签认**。
- **延迟门禁回执不得回填在场**：门禁同时记录 `occurred_at`（真实刷卡时刻）与
  `received_at`（回执到达时刻）。在场与空档**只按 `occurred_at` 推导**；
  只有孤立的 `out`、从无 `in` 时，绝不臆造进入时间。
- **无人监护空档**：原监护人 `out` 到接班人 `in` 之间计为空档；接班人先到（重叠交接）
  或原监护人未离场则无空档；接班人未到场时空档持续（`open=true`），供班组长查看。
- **交接历史时间线**：按实际时刻排序，清晰呈现
  停工 → 离场 → 到场 → 签认 → 交接完成 → 申请复工 →（批准/驳回）复工。

## 现场演练建议（覆盖三类必测场景）

1. **换班空档**：对「反应釜 R-201」发起交接 → 原监护人签认后刷卡离开 →
   等待若干秒 → 接班人刷卡进入再签认，时间线与班组长页可见该空档时长。
2. **资质过期**：选择接班人 **孙卫民（资质已过期）** 完成交接并申请复工，
   班组长页「批准」按钮被禁用/接口返回 `resume_blocked`；可调用资质续期接口后再试。
3. **重复签认**：同一人对同一角色反复点签认，签认条数始终为 1；
   再次发起交接返回「已有进行中的交接」。
4. **延迟回执**：门禁区把「回执延迟(秒)」设为 60，再刷卡；系统标注延迟但按真实时刻计，
   只补来一条 `out` 不会让人被判定为在场。

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/handovers/start` | 停工并发起交接 |
| POST | `/api/handovers/{id}/sign` | 本人账号签认（幂等） |
| POST | `/api/access` | 门禁刷卡（可带历史 `occurred_at` 模拟延迟回执） |
| POST | `/api/handovers/{id}/resume-request` | 接班人申请复工 |
| POST | `/api/resume-requests/{id}/decision` | 班组长审批（硬条件不满足则拒绝） |
| GET | `/api/jobs/{id}/handover` | 交接详情 + 空档 + 复工预检 |
| GET | `/api/leader/overview` | 班组长：无人监护时间段 |
| GET | `/api/jobs/{id}/timeline` | 交接历史时间线 |
| POST | `/api/persons/{id}/cert` | 资质续期（验证过期/恢复） |

交互式文档见 `http://localhost:8000/docs`。
